A **project** groups the applications, databases, and volumes it depends on, plus its own backup destinations and shared environment variables. It's the unit you deploy, back up, and reason about together.

<Screenshot name="project-overview" alt="A project's services table with status pills and the ratio-coloured running count." />

## Create a Project

**New Project** asks for a name and a slug, auto-derived from the name (lowercase, numbers, and hyphens) but editable before you save. 

Creating a project also creates its own private Docker network behind the scenes — it's what every application and database you add will join.

A project has four tabs: **Overview**, **Backups** ([destinations](/docs/core/project/backup-destinations) and recent activity), **Env Vars**, and **Settings**.

## Network

Every project gets one private Docker bridge network, created the first time it's needed. Every application and database added to the project joins that same network, which is what lets them reach each other by container name, e.g. an app talking to its database at `db-hostname:5432`, without being reachable from any other project. 

<Callout type="info">
See [Architecture](/docs/core/architecture#networking) for how this fits into the bigger picture.
</Callout>

## Environment Variables

The **Env Vars** tab holds variables inherited by every application in the project; set a database URL or a shared API key once, and every app in the project sees it. 

An application can still define its own variable with the same key, which wins over the project-level one; see [Environment variables](/docs/core/application/environment-variables) for that per-app behavior. Variables can be added one at a time or pasted in bulk from an existing `.env` file, and each can be flagged as a secret to mask its value in the UI.

## Sharing

A project has one owner, but the owner can share it with every Member on the install — so a team can collaborate on a project without promoting everyone to Admin just to get access.

Sharing is a single switch on the project's **Settings** tab, **Share with every Member**, off by default — nothing changes for a project until its owner turns it on. Once shared, every Member can view and work in it: deploy, create databases, edit environment variables, all of it.

**Destructive rights stay owner-only.** A shared Member cannot delete an application, database, or domain, transfer the project, or unshare it — only the owner (or an admin) can. Sharing widens who can *use* a project, not who can destroy it.

Sharing isn't admin-only: a Member who owns a project can turn it on themselves. If it required an admin, the ability to collaborate would depend on someone else's time, not the owner's.

## Settings and Deletion

The **Settings** tab shows the project's ID, slug, and timestamps, lets you rename it, and reassign it to a different owner (admin only). 

The **Danger Zone** deletes the project, and every application/database in it, permanently. There's no undo once it goes through.
