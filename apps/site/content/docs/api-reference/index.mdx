This is the full endpoint reference — every route the API registers, one table per domain in the sidebar. If you're looking for how to authenticate, the scope ladder, or a walkthrough of common tasks, start at [API Access](/docs/api-access) instead; this page is for looking up one specific endpoint by name or path.

<Callout type="warn">
**Generated, not written.** Each table is produced by probing the real, running router with a personal access token and recording what actually happens — not by reading the source and describing what it's supposed to do. A hand-written version of this reference has gone stale twice in the weeks before this page existed; a generated one can't drift the same way, because it IS the observed behavior.
</Callout>

## What Each Table Shows

- **Scope** — the narrowest [scope](/docs/api-access#scopes) a token needs to reach this endpoint.
- **Notes** — flags that don't fit the other columns:
  - `project-pinned` — a token pinned to one project is rejected outside it.
  - `admin role required` — the token's owner must be an Admin, regardless of scope.
  - `session required` — no token, at any scope, can reach this endpoint; only a live dashboard session can. See [what a token can never do](/docs/api-access#what-a-token-can-never-do).
  - `session gate not probed` — a small number of routes (destructive admin actions with no id in the path, like triggering a cleanup) aren't safe to actually execute during generation, so this one signal is read from the zero-scope probe alone rather than confirmed by executing the route. The scope column is still fully accurate; only whether the route is *additionally* session-gated is unconfirmed for these rows.

## What This Page Doesn't Cover

Request and response bodies. The generator observes status codes and error messages, not payload shapes — it can tell you an endpoint needs `write` scope, not what JSON to send it or what comes back. For that, the request/response types in `apps/api/internal/handler` are the source of truth today.

## Regenerating

```bash
task generate:api-docs
```

Runs against a disposable database — nothing it does touches a real install. Commit the result; Cloudflare Pages builds this site from `main` with no Go toolchain and no running API, so the output has to already be there.
